## 完整命令与排查工具

### 命令行跑

```bash
# 离线自检，不消耗额度（先把引擎/渲染/审计链路跑通）
python run_text.py --stub --seats 9

# 全部自测（胜负判定 / 玩法规则 / 抽卡 / 闸门 / 信息隔离 / 响应解析 / 多通道 / 前端）
python tools/run_all_tests.py

# 只跑前端（真实 DOM + 真实 petite-vue，需要先 npm install 装 jsdom）
node tools/selftest_frontend.js

# 单步调试
python run_text.py --seats 5 --step

# 看一眼某个座位的完整 prompt（不调 API）
python run_text.py --seats 5 --dump-prompt 1 --dump-phase NIGHT_WOLF_CHAT

# 真实对局
python run_text.py --seats 5 --max-days 4
python run_text.py --seats 9

# 换通道 / 换模型之前先量一次：思考 token 会不会把输出额度吃光（⚠️ 会花额度）
python tools/probe_reasoning.py                       # 默认测 ep2 上座位配的模型
python tools/probe_reasoning.py --phase wolf glm-5.3-flash glm-5.2
```

跑完一局想看数据，有两个不用开浏览器的工具：

```bash
# 盯着正在跑的一局（SSE），结束自动汇总（要花时间的那一步会打 ★）
node tools/watch_game.mjs                  # 端口用 WOLF_PORT 覆盖，默认 8099

# 把跑完的一局算成 M2 报告：逐座延迟 / 缓存命中 / 截断 / 重试 / 隔离审计
python tools/report_run.py runs/20261005_131915_9seat_web

# 上面那份报告说"某座某阶段截断了"，往下钻的四把起子：
python tools/inspect_calls.py runs/<局>                 # 每次调用的额度/截断/耗时总表
python tools/inspect_calls.py runs/<局> --truncated     # 只看被截断的
python tools/inspect_failures.py runs/<局>              # 只看失败/零延迟的（含 models_tried、原始错误）
python tools/dump_call.py runs/<局> 7 3 DAY_SPEECH      # 某一条的全貌：usage / 正文 / 推理长度
```

> **`runs/<局>` 里的 `messages` 是原样存的，所以失败能"重放"。**
> `tools/replay_call.py` 把某一次真实调用重新发出去，只改你想试的那个旋钮
> （`--no-thinking` / `--max-tokens N` / `--model` / `--endpoint`），
> 用来回答"换个参数会怎样"——**不要**用手写的小 prompt 去猜：
> 思维链吃光额度这类问题只在真实盘面（第 3 天、10 个座位的历史）下才复现。
>
> ```bash
> python tools/replay_call.py runs/<局> --list                      # 先看这一局有哪些调用
> python tools/replay_call.py runs/<局> 7 3 DAY_SPEECH --no-thinking
> python tools/replay_call.py runs/<局> 7 3 DAY_SPEECH --max-tokens 32768
> ```
>
> ⚠️ 这三个**真的会调 API、花额度**（`replay_call.py` 默认只发一次，不做 relay 那套翻倍重试）。

> `report_run.py` 只读 `events.jsonl` + `seat_*.jsonl`，而且**角色是从事件流反推的**
> （小桌出现过的人就是狼），所以不用记 seed。两条路径（CLI 和浏览器）现在都会写
> `summary.json`，这个脚本是"想快速看一眼逐座延迟/缓存/审计"时用的。

> **只有前端自测需要装依赖**（`npm install` 拉一个 jsdom，一次就够）。
> 跑对局本身不需要 node：`python server.py` 直接用，petite-vue 是仓库里的本地文件
> （`static/vendor/petite-vue.iife.js`，离线可用）。


### 这一局花了多少

`summary.json` 现在有**输出侧**口径：`completion_tokens_total` /
`reasoning_tokens_total` / `wasted_completion_tokens_total`；
`python tools/report_run.py runs/<局>` 会多打一张逐座成本表。

两局实测（10 座局与 M2 基准局）：

| | 输出 tokens | 其中思维链 | 思维链占比 |
|---|---|---|---|
| `20261006_011857_10seat_web` | 149,728 | 121,096 | **81%** |
| `20261005_131915_9seat_web` | 101,442 | 73,008 | **72%** |

**钱主要花在"想"上。** 关掉思维链的座位几乎不花钱（豆包 4 次调用 930 tokens、
MiniMax 0 思维链），而 GLM 一座就占全场输出的 34%（8 次调用 51,326 tokens，98% 是思维链）。

`wasted_completion_tokens` 是**被翻倍重试/超时而丢弃的那些尝试**——它们同样计费，
以前只记最终那次的 `usage`，这笔钱在账单上是隐形的。
2026-10-06 起每次尝试都记进 `attempts_detail`（含 `max_tokens` / 消耗 / 丢弃原因），
`tools/inspect_calls.py --full` 能逐条展开看。

> 老对局（2026-10-06 之前）的 `wasted` 显示 `?`——**不是没烧，是当时没记账**。

每局输出到 `runs/<时间戳>_<座位数>/`：

```
runs/20261004_182248_5seat/
├── events.jsonl      # 权威事件流，回放唯一数据源
├── seat_1.jsonl      # 每座：完整 messages / 原始响应 / usage / 缓存命中 / 截断标记
├── ... seat_9.jsonl
└── summary.json      # 结果、成本统计（含推理/白烧 token）、隔离审计、输出质量
```


## 局后感言（赛后采访）

一局打完之后，可以让每个座位**回头聊两句**。这和遗言是两件事：遗言是局内机制
（`DAY_LAST_WORDS`，被放逐时说一句），感言是**对局彻底结束、全员身份摊开之后**
的赛后复盘，它不改动任何游戏状态。

```bash
# 先看看能不能读回来、prompt 长什么样（不花钱）
python tools/reflect.py runs/20261006_011857_10seat_web --dry-run

# 真跑（逐座位顺序进行，后面的人能看到前面的人说了什么）
python tools/reflect.py runs/20261006_011857_10seat_web

# 钱包紧：只让 3、7、10 号说
python tools/reflect.py runs/<局> --seats 3,7,10

# 不联网验证管路
python tools/reflect.py runs/<局> --stub --force
```

产物是 `runs/<局>/reflections.json`。三条设计约束：

- **绝不污染对局记录。** 感言不写 `events.jsonl`、也不写 `seat_*.jsonl`
  —— 那是权威对局记录，报告/回放/隔离审计全靠它。感言的调用日志单独放
  `reflect_logs/`。自测里有一条断言专门守这件事。
- **后面的人能听到前面的。** 台词按座位顺序累积进 transcript，所以它更像赛后发布会
  而不是十份互不相干的作文 —— 有人会回应、有人会不服。
- **依然不出现模型名。** 局内规则是"一律用座位号指代"，赛后也一样；
  模型名只出现在给观众看的结果文件里。

身份取自 `summary.json`（权威），**不靠反推** —— `report_run.py` 那套"谁在小桌
出现过谁是狼"会把猎人和守卫一律猜成村民。

**对局本身就是持久的**：`runs/<局>/` 里 `events.jsonl` + `summary.json` 齐了就随时
能重开复盘，重启服务不影响。所以"打完这局再重启，然后让他们发表感言"这个流程
天然成立。

## 玩法规则

规则机在 `aiwolf/engine.py`，动作协议在 `aiwolf/protocol.py`。
下面六条是 M1 之后补上的 —— 每一条都对应一个**会让博弈退化或把信息白丢**的地方
（详细来龙去脉见 [`DESIGN.md`](DESIGN.md) 第 11 节，2026-10-06 那一批见第 13 节）：

| 规则 | 说明 |
|---|---|
| **投票理由进大桌** | 投票阶段的 `speech` 以前被丢弃，只剩「N号 投给 X号」。现在理由会作为公开事件落进大桌 —— 后置位看得到"他为什么投这个人" |
| **狼队多数表决** | 刀口不再由"最后一只发言的狼"独裁；按票数汇总，平票时按**谁先提出**定，决议（几比几、谁提的）记进小桌 |
| **猎人天亮立刻开枪** | 夜里被刀的猎人，在公布死讯后立刻开枪（被毒不能开），枪口结果影响当天的发言与投票 |
| **平票 PK** | 平票 → 平票者 PK 发言 → **台外玩家**在 PK 台上重投（台上无投票权）→ 再平票才无人出局 |
| **狼人自曝** | 白天发言时 `action.type` 填 `explode`（也认「自曝/自爆/认狼」）：**自曝者当场出局**，白天立即结束、当天不投票、直接进黑夜 |
| **白痴** | 被投票放逐时翻牌、**本轮不出局**，从此失去投票权（还能发言）。免死只有一次，再次被投就正常出局；被刀/被毒照常死。★ 2026-10-11 修：公告原来把**所有**没投票的人都写成"已翻牌白痴"，PK 重投时台上两个平票者因此被公开宣布成翻牌白痴（本局其实一张白痴牌都没翻），把全场读盘带歪 |
| **警长** | 首日竞选 → **只有没上警的人**投警长票 → 平票 PK 再投 → 再平票**警徽流失**。警长在放逐投票里算 **1.5 票**，每天决定从**警左/警右**开始发言（自己最后归票），出局时**移交警徽或撕掉** |
| **历史立场** | 尾部块写着「你投过谁、谁投过你、你提过什么刀口、你上一次公开发言的原文」，专治长局里的自相矛盾**和换人代打后的立场断裂**。只进尾部块，**不碰共享前缀**，缓存设计不受影响 |
| **上一轮的想法** | 座位自己的 `thinking`（私密草稿）会回灌给**它自己**：截断 400 字、自动抹掉模型名。同一座位一天内换了三个模型时，这是唯一能传递"我本来想干什么"的东西 |
| **狼队友死活** | 「你的狼队友」分成「还在场 / 已出局」两行，私密信息里另给一句"你还有 N 名活着的队友 / 你是最后一张狼"。实测代打模型把活着的队友当成已出局，于是放弃保队友只顾自保 |
| **刀口不外泄** | 天亮公告只有「平安夜 / 昨晚死亡的是谁」。原来公开频道会播一条「X号 昨晚被救下了」，等于把刀口公告给全场 —— 实测成了全场锁死真预言家的"越权信息"（那条信息本来就是引擎自己播的） |
| **元层面话术（狼队专属）** | 「系统故障」（装掉线、上下文截断）与**假装"撞墙"**（自称是模型、不能参与欺骗、要退出）：只是 `speech` 里的一句台词，**action 照真实计划填**。**两种用法**：① 自保（被锁定时装掉线，把自己从票型里划掉）；② **栽赃**（"崩溃"比普通发言更像真话 → 临终点名一个好人、或等别人踩你最凶时崩溃嫁祸他，让好人的票打到好人身上）。可信度一次性，代价是牺牲本轮话语权。对手同样可能对你用 —— **"临终点名"可能只是狼在栽赃**。**这张牌只注入狼人的动态角色提示词（`WOLF_DAY`/`WOLF_VOTE`），不在全局规则里** —— 全局那节 9 个座位一起读，好人觉得与己无关、狼人读完也想不起来，实测没效果；放进尾部块才是"发言前最后读到的那一段" |

**结算动画**：Web 端由 `static/index.html` 的 `#winFx` 弹层渲染
（狼人获胜红月 + 震屏、好人获胜金光、平局中性；点击或 7 秒后关闭，`aborted/error` 不弹）；
文本版是 `run_text.py` 的 `print_result_banner()`。

> 警长（警徽 1.5 票、警左/警右、警徽移交）**已上线（2026-10-06）**，走的是"方案 A"：
> 只有**没上警**的人投警长票、平票台上 PK 再投一次、再平票警徽流失、警长自己最后发言（归票位）、
> 出局时移交警徽或撕掉。
>
> 它和原来的"每局随机抽发言起始座"**直接冲突** —— 有警长时发言顺序改由警长决定，
> 随机起始座只在没有警长时才生效。开关是 `config/seats.json` 的 `game.sheriff_enabled`：
> 关掉就回到老行为。**开着的话首日竞选会给每个存活座位各加一次调用**（12 座 = +12 次）。
>
> ⚠️ **"没实现"不等于模型会当它不存在。** 在警长上线之前，实测 10 座局里好几个模型
> 凭空发明了警长和警徽流（那是 12 人警长板的术语）：6、7 号拿"3号首日没报验人顺序
> （警徽流）"当定狼硬伤，8 号一本正经地报了警徽流，2 号只好花一整段去纠正
> "本轮并没有警长竞选"。这条完全不成立的指控，实际成了第 1 天放逐**真预言家**的理由之一。
>
> 另外 `aiwolf/render.py` 的 `board_notice()` 会把板子写进 system 消息（所有座位
> 字节级相同，不破坏共享前缀、也不泄漏任何东西）：
>
> ```
> # 本局板子（公开信息）
> - 共 12 名玩家：狼人 4 名、预言家 1 名、女巫 1 名、猎人 1 名、白痴 1 名、村民 4 名。
> - 本局有警长（首日竞选产生）。
> ```
>
> 有没有警长由 `sheriff_enabled` 决定 —— 板子公告必须跟着变，否则又是"提示词和引擎
> 各说一套"（§4.3 那条教训）。
>
> 所以现在 `aiwolf/render.py` 的 `board_notice()` 会把板子写进 system 消息（所有座位
> 字节级相同，不破坏共享前缀、也不泄漏任何东西）：
>
> ```
> # 本局板子（公开信息）
> - 共 10 名玩家：狼人 3 名、预言家 1 名、女巫 1 名、猎人 1 名、守卫 1 名、村民 3 名。
> - 本局没有警长，也没有警徽、警徽流、警长竞选、警徽移交。
> ```
>
> **只写公告，不写说教。** 初版还带了"不要要求别人报验人顺序"、"引用不存在的机制
> 会暴露你在套用别的板子"之类的告诫，被砍掉了 —— 一是啰嗦，二是**"警徽流"这个
> 不存在的词在一条公告里被重复四遍，反而反复给它加权重**，更容易被模型抓去用。
> 自测里有一条断言专门防它长回去（不许出现"不要"、全文必须短于 200 字、
> "警徽流"只准出现一次）。
>
> **同类问题还有一处，更根本：目标合法性。** 引擎校验和提示词本来各写一套，结果
> 两头都错 —— 引擎强制"不能选自己"而提示词只列"存活"（模型选自己完全合理，
> 然后被判非法且不解释）；提示词跟守卫承诺"不能连守同一人"而校验里压根没实现。
> 现在需要指定目标的阶段（守卫/预言家/女巫/狼刀/猎人）会把引擎算出的
> **可选目标**直接写进尾部块：
>
> ```
> ## 当前局势
> 第 1 天 · 守卫守护
> 存活：1号、2号、…、10号
> 出局：无
> 可选目标（只能从这些座位里选）：1号、2号、4号、…、10号
> ```
>
> 同一份清单既进提示词、也拿去做校验，同源，不可能再分叉。
> "目标不合法"五条路径的行为也统一了（以前女巫/狼人/猎人会**静默吞掉动作**）。


## 角色抽卡

角色**每局随机抽**，不按座位顺序发。早期是按顺序发的，结果 1-3 号永远是狼，
而 1、2 号恰好是 Gemini 和 GPT —— 几局下来就会被看出"某某总是狼"。
现在每局抽一次并记录种子，随时可复现。

- 分布经卡方检验：5 人局每座当狼 40%、其余三种角色各 20%（χ²=2.75, 自由度 4）
- `role_seed` 为 `null` = 每局随机；写死一个数字 = 每局一样（可复现调试）
- `shuffle_roles: false` = 回到固定顺序

**另一个同类偏差也修了**：发言顺序不再永远从 1 号开始，而是每局从随机座位起顺时针。
否则座位号小的模型永远吃首置位的亏（信息最少、最容易被打）。


## 调试闸门

对局可以**强制暂停 / 单步 / 强制结束**，都挂在引擎每次调用模型之前。

| 操作 | 行为 |
|---|---|
| **暂停** | 下一次调用前停下，不发请求、不烧额度 |
| **单步** | 放行 1 次调用后重新停住（可连点叠加） |
| **结束** | 杀掉在途请求，立刻终止对局（实测 0.3s） |

> **暂停拦不住已经在飞的请求。** 点暂停时如果正好有一个请求发出去了，要等它回来
> 才会真正停在闸门上。页面上会明确区分这两种状态：显示「对局线程已停在闸门」
> 还是「有 N 个请求在飞」。

命令行也可以单步：

```bash
python run_text.py --seats 5 --step     # 每次调用前停下来按回车
```

### 前端要不要拆 / 要不要换框架

**已经拆完了**（2026-10-05）：`index.html` 从 1341 行降到 ~300 行，只剩骨架和模板；
CSS 独立成 `app.css`；JS 按职责拆成 8 个 ES 模块。渲染层换成 **petite-vue**
（本地 vendored，约 17KB，**无构建步骤**）—— 原来满屏的 `innerHTML = ...` 拼接没了，
改成模板 + 响应式状态。

为什么值得换：原来 `renderFeed()` 每次事件都**整块重建大桌 DOM**，
M3 想加气泡入场 / 日夜转场时，动画会被每来一条新消息重置重放，滚动位置也被强行拉到底。
现在 v-for 带 `:key`，新消息只追加、已有节点原地保留 —— 自测里专门有一条断言守这个行为。

还留在命令式的部分：**配置抽屉**（`app/drawer.js`）。它只在用户操作时重画，
不属于 SSE 热路径，先原样搬过来降低风险。

**这版 petite-vue 前端是过渡态**——它解决了 DOM 重建，但没解决「增量状态」和
「只能看当前一局」。

## 四条必须守住的规则

改这份代码之前请先读 [`DESIGN.md`](DESIGN.md) 第 3 节。这四条违反任何一条，
缓存设计就作废、信息隔离就破了、或者博弈就退化了：

1. **身份卡放尾部，不放开头。** 放开头会让 9 个座位从 token 0 分叉，
   大桌前缀完全无法共享缓存。
2. **自己的发言也用 `user` 角色。** 用 `assistant` 会让每个座位在"自己发言的那一轮"
   分叉，共享前缀最晚第 9 轮断掉。
3. **角色差异只能进尾部块。** 任何座位相关的信息混进共享前缀，
   `check_shared_prefix()` 会立刻抓住。
4. **绝不暴露模型身份。** 所有玩家一律以座位号指代（"3号"），
   狼队友也只写"X号、Y号"。让模型知道"2号是 GPT 所以偏理智"，
   它就会去读模型画像而不是读发言逻辑。

每次运行都会自动跑这三个守卫：

```
-- 渲染不变量预检 --
  ✅ 开局（空前缀）：9 个座位的共享前缀逐字节相同（1 条消息），尾部块各不相同
  ✅ 尾部块不含任何模型名（队友只以座位号出现）
  ✅ 终局（完整前缀）：9 个座位的共享前缀逐字节相同（50 条消息），尾部块各不相同

信息隔离审计
✅ 通过：没有任何座位看到越权信息
```

## 实测得到的几条硬约束

全部来自 [PROBE_FINDINGS.md](PROBE_FINDINGS.md)，写进代码前请先确认没被绕过：

| 约束 | 位置 |
|---|---|
| 推理型模型会把 `max_tokens` 全花在 `reasoning_content` 上，`content` 返回空串 | `relay.extract_text()` |
| 输出被截断（`finish_reason=length`）是 JSON 解析失败的头号原因 | `protocol._salvage_truncated()` |
| `kimi-k3` 只接受 `temperature=1`，传其它直接 400 | `config` 的 `temperature_locked_models` |
| `grok` 有模型级并发上限，8 并发触发 429 | `config` 的 `per_seat_overrides` |
| **Gemini 全系不吃前缀缓存**（3.8/3.7/3.6/3.5/3.1/2.5 全测过，`cached_tokens` 恒为 0） | `audit_prompts()` 里的 `avg_cache_ratio` |
| 网关的 `prompt_tokens` 普遍高于本地估算（Claude 约 1.7 倍） | 成本核算按实测 token 算 |

### 代打（fallback）：已开启

`config/seats.json` 里 `fallback_enabled: true`。主模型失败后按该座位的 `fallback`
列表依次尝试，成功即用，并在 `LLMResult.substituted` / `stats` / `summary.json`
的 `calls_substituted` 里留痕。

**四条策略**（都在 `game` 段，改数字即可，不用动代码）：

| 旋钮 | 默认 | 作用 |
|---|---|---|
| `max_attempts_per_model` | 2 | 同一个模型最多试几次（试满才换人） |
| `switch_model_on_timeout` | true | **超时/挂起时立刻换下一个模型** —— 上游挂起不会因为等 2 秒就恢复，死磕一次就是 240s |
| `call_deadline_s` | 600 | 一次调用（含所有代打尝试）的总时长上限，兜住最坏情况 |
| `request_timeout_s` | 240 | 单次请求超时。想快速验证代打，把它调小（比如 60） |

429 / 5xx 仍然按退避重试（那些会自愈）；只有"连上了但一个字节都不回"才立刻换人。

**代打要看得见，但不能让玩家看见。** 写进大桌就等于告诉所有人"4 号换了张牌"，
正好踩了下面第 4 条规则。所以代打只记成**上帝视角事件**：行动日志里能看到
`（上帝）4号 Doubao 主模型 … 失败，改由 … 代打`，任何座位的 prompt 里都不会出现。
统计上也分得开：`summary.json` 的每条 call 都有 `model_used` 和 `substituted`，
所以"这一手到底是谁出的"永远查得到。

### 在页面上配代打

⚙ 配置 → 第 5 节「代打与超时」：

- 总开关 + 三个数字（每模型尝试次数、单次超时、整次总时限、超时是否立刻换人）
  —— 走 `/api/gamecfg`，**改完下一局生效**（config 在开局时才读）
- 每个座位的**代打链**，每档就是一个 `[端点 ▾] → [模型]`：

```
1 Grok   grok-4-5 @ep3            ＋ 加一档
  [豆包(火山方舟) ▾] → [ep-20261005143108-gcv24]  ✕
  [claude官方    ▾] → [claude-sonnet-5]           ✕
```

模型框挂了该通道的模型清单（`datalist`），**可下拉可选、也能直接填** ——
推理接入点（方舟的 `ep-xxxx`）不在通道目录里，必须允许手填。
存储格式仍是 `模型@通道`（`glm-5.2@ep2`），所以 config 手改和页面改是同一份东西。

> 引用了已经不在端点池里的通道时，下拉会**保留原值并标 ⚠**，不会静默回落到
> "默认通道" —— 那会把 `@ep2` 悄悄抹掉。

`模型@通道` 里的 `@通道` 可以省（省了走默认路由）。**跨厂商代打必须写 `@通道`**
—— 一个座位只绑一条通道，而 grok 在 ep3、豆包在 ep4：

| 写法 | 含义 |
|---|---|
| `gpt-5.5` | 用该座位绑定的通道；跑不了就挑一条能跑它的 |
| `ep-…@ep4` | **明确指定**走 ep4（推理接入点不在任何通道的目录里，猜不出来） |
| `{"model":"…","endpoint":"ep4"}` | 对象形式（config 里也兼容，等价于上面） |

> **跨通道是硬规则**：`fallback` 的第一档**必须落在另一条通道上**，同族备选排第二。
> 依据是 2026-10-05 的三座测试：ep3（中转站 A）整条通道在 reset 连接，
> 2 号座的三个模型全在 ep3 上，代打走完了也全军覆没
> （`attempts=4, model_used="", substituted=False`）；3 号座第一档是跨通道的豆包（ep4），
> 活下来了。`tools/selftest_fallback.py` 会检查**每一个**座位的判定（是断言，不是打印）。
> 代打救不了的是"所有通道一起挂" —— 那时只能靠 `call_deadline_s` 及时止损。
>
> **2026-10-06 这条规则抓到了一个真人漏网的**：10 号座的代打链
> （`gpt-6-luna` / `gpt-5.6-sol`）整条都在 ep3 上，和主模型同通道。10 座局里
> ep3 连接超时（三个模型都是 `curl (28) Connection timed out after 15011 ms`），
> 10 号座**连着丢了两个回合**。原因有二：配置本身违规，而且当时那条审计
> 只扫前 9 座、还只 `print` 不 `check`，所以从来没报出来。两处都修了。

## 多通道（多个 base_url + key）

**为什么需要**：并发额度是按 **key** 算的。同一个 key 上撞到
`concurrency_limit_exceeded`，那个座位就直接"未发言"——光调低限流治不好，
因为额度本来就是共享的。真正的解法是**多把 key、多条通道**，
每条通道各自维护一份并发预算。

> ⚠️ **但现在对单局没有影响 —— 引擎是串行的。**
> `aiwolf/` 里没有任何并行调用（唯一的线程是 `GameRunner` 对局循环和通道模型刷新），
> 任意时刻只有 **1 个请求在飞**。所以 `Endpoint.concurrency` 和
> `seats.json` 的 `concurrency.global` 在**一局之内永远不会成为瓶颈**：
> 每通道 5、全局 8 也好，每通道 1、全局 1 也好，跑出来的结果一模一样。
>
> 它们真正起作用的场景只有两个：**通道模型清单刷新**（后台线程，可能与对局重叠），
> 以及**将来做并行调用**的时候（12 个座位同时发言）。
> 要并行的话，`concurrency.global` 才是总闸门 —— 各通道配 5×5=25 也会被它卡在 8。

**怎么配**：打开页面 → 顶部「⚙ 通道设置」→ 填 `base_url` + `api_key` + 并发数。
- 保存后**立即落盘**到 `config/endpoints.json`，重启自动读回
- 保存后**自动拉取**该通道的 `/v1/models`，座位模型下拉直接选
- 同一中转站可以配多条（不同 key）；同一个 base_url+key 也允许重复登记
- 座位**轮转分配**到各通道，且同一座位永远落在同一通道（不打断前缀缓存）
- 也可以在每个座位上手动指定通道和模型，同样落盘到 `config/seats.json`

> ⚠️ **同一个 key 拆成多条通道并不能绕开并发上限**——网关那边是按 key 计的。
> 必须是真的不同的 key（或不同中转站）才有效果。

> 🔒 **整个 `config/` 都不提交**：`endpoints.json` 里存的是**明文 key**，
> `seats.json` 里有通道地址与本机代理。首次运行先 `cp -r config.example config`，
> 详见 [`config.example/`](../config.example/)。页面回显时只给掩码（`EwI3***O5R`）。

**模型不再是固定九个**：多通道下每个通道能提供的模型以实际拉取为准，
所以座位上的模型可能和你预设的不一样。页面上的下拉就是实际在架的清单。


## 出站代理（海外通道被 reset 时）

有些海外中转站会被**按主机名**在传输层阻断：TCP 连得上、TLS 握手被 RST，
明文 80 也一样。实测过的表现是整条通道全灭——2026-10-11 那局，
`中转站 C`（ep11/ep12，也就是 2号 GPT 和 10号 Claude）**一次都没成功**，
17 次调用全走代打，表面上 12 个模型家族实际只剩 10 个。

> 这和 Cloudflare 的 bot 规则**不是一回事**。CF 那个是带响应体的
> `403 error code: 1010`（`DEFAULT_UA` 修的是它）；而握手阶段的 RST
> 发生在任何 HTTP 字节之前，**UA 根本发不出去，换 UA 没用**。

配置（`config/seats.json` 的 `relay` 段）：

```json
"relay": {
  "proxy": "http://127.0.0.1:7890"
}
```

- 优先级：`relay.proxy`（config）> 环境变量（`HTTPS_PROXY` / `http_proxy` / `ALL_PROXY` 等）> 直连
- 留空字符串就是直连；端口改成你自己的即可（上面 7890 是 Clash 之类的常见 mixed 端口）
- Clash 的 mixed 端口：国内通道直连还是走代理由代理端规则决定，
  代码不做 `no_proxy`（免得和代理端规则打架）
- urllib 和 curl **两条传输都吃这个设置**（`curl` 加 `-x`）——只配 urllib 不够，
  「强制结束」那条路走的是 curl
- 启动时会打一行 `[relay] 出站代理：...`，挂没挂上一眼能看到

验证一条通道是否真的活了（把端口换成你的）：

```bash
curl -sS -x http://127.0.0.1:<代理端口> -o /dev/null -w "%{http_code}\n" https://relay-a.example/v1/models
```


## 故障排查：某个座位"凭空消失"

调试时最容易遇到的现象是——大桌上某个座位没说话，看起来像被跳过了。
**实际上它从来没有"被跳过"，而是调用失败了，而失败可能被藏起来了。**

已经遇到并修掉的三种原因：

| 症状 | 真正原因 | 修法 |
|---|---|---|
| 响应 200，但"正文与推理都为空" | 网关把推理放在 `reasoning` 字段，代码只读 `reasoning_content`（GLM 就是这样） | `extract_text()` 读 5 种字段名 + legacy `text` |
| 响应 200，正文为空，`finish_reason=length` | 重推理模型把整个输出额度花在自己的思维链上，一个字正文都没吐 | 检测到就**把预算翻倍重试**（上限 `game.max_tokens_cap`，默认 **32768**），并**记住该座位需要的预算**；翻到上限还是 `length` 就**换下一个代打模型**，不把半截 JSON 当成功 |
| 响应 200，正文只剩几个字符 + `length` | **上限本身定得太低**：10 座局第 3 天 GLM 5.2 花了 16380 个思维链 token，正文只剩 `\n{"`，撞 16384 上限就被收下了 | 上限提到 32768（同一份 prompt 实测 **16898** tokens 就正常写完，差 514）；上限改成可配 |
| 429 / `concurrency_limit_exceeded` | 网关的**按 key** 并发上限（Grok 尤其明显） | 限流退避从 1~4 秒改成 5~15 秒；**配多通道**从根上摊开 |

还有一个**会悄悄吃掉动作**的坑：模型经常不按约定的英文枚举回答。
实测 Claude 返回 `{"type": "击杀", "target": 2}` —— 早期代码识别不出
`"击杀"`，把它降级成 `pass`，**狼的刀就凭空丢了**。
现在动作别名表覆盖中英文同义词，按模式长度倒序匹配（`"毒杀"` 不会被
误判成 `"杀"`）。

兜底保障：**任何座位说不出话，大桌上都会留一条中性的「本轮未发言」**，
而不是静默跳号。这样其他模型和看页面的人看到的是同一件事。

> **轻型重推理模型不要选。** 实测 `glm-5.3-flash` 和 `kimi-k2.6` 会把 3072 输出额度
> 全烧在思维链上，单次发言 104~406 秒，9 座局根本跑不完。
> 同样 prompt 下 `glm-5.2` 是 22.5 秒、`kimi-k2.7-code` 是 8.6 秒。
> config 里这两座已经换掉，原型号保留在 fallback 里，想换回改 `model` 即可。


## 信息隔离审计

审计对象是 `seat_*.jsonl` 里**实际发出去的完整 messages**，不是重建的视图——
只有这样才能证明"真的没漏"。它会检查：

- 村民座位的 prompt 里不出现任何 WOLF 频道内容
- 村民座位的 prompt 里不出现"狼队夜间频道"这个标题
- 任何座位的 prompt 里不出现**别人**的私密信息（查验结果、药水状态、狼队友名单）

`tools/selftest_invariants.py` 会**故意制造泄漏**来证明这两个守卫不是空检查。
一个从不失败的检查等于没有检查。
